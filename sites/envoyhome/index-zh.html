一个住在你电脑里的家庭智能体

EnvoyHome 是一个自托管、安全优先的家庭智能体：对话、记忆、文档知识库、静态工作流、审批，以及可选的智能家居控制——全部运行在你自己的机器上。桌面和手机只是望向它的窗口。

EnvoyHome 是什么？

一个属于你的家庭智能体——不是套了家庭外壳的云端聊天机器人。

EnvoyHome 是 EnvoyMesh 应用家族中的家庭智能体。核心就是智能体循环本身：envoy-harness、静态工作流、记忆、审批，以及一整套智能体可调用的工具——文件、网页、浏览器、办公文档、技能、计划任务、MCP 等等。

智能体住在家庭电脑上。密钥、会话记录、沙箱和智能家居凭据都留在那里。桌面和手机通过 home.* 通道接入；它们是窗口，不是大脑。

智能家居只是这些能力中的一个工具面——当你接入 hub 时有用，但从不定义这个产品。EnvoyHome 用自然语言、审批和工作流来增强 Home Assistant 与 MQTT；它不替代你的 hub，也不附带社交网络。

🏠

智能体留在家里

每一次对话、工作流和计划任务都经过家庭守护进程。轻客户端只是重新连回来——它们从不持有模型密钥，也不运行智能体循环。

🔁

工作流不是第二套引擎

用可视化图或 YAML 编写静态 DAG，也可以从自然语言起草。工作流节点调用与对话相同的工具，也走相同的审批。

🛡️

先审批，再产生后果

持久化的待审批、默认 600 秒 TTL、失败即拒绝，以及绑定到已解析调用的授权——而不是一个“智能体可以做任何事”的总开关。

🧠

谨慎学习的记忆

档案、常驻笔记、每日记录、情景检索、KnowYou、文档知识库与技能——持久写入由 PendingLearn 把关。

👨‍👩‍👧

一个智能体，多位家人

家庭档案共享同一个智能体，但记忆、文件与策略彼此隔离。手机配对到家庭，每台设备只被允许代表它绑定的账户。

🔀

云端、本地，或谨慎混用

接入 OpenAI 兼容或 Anthropic 兼容的提供商，本地运行 llama.cpp，或连接 Ollama。隐私模式会强制本地推理，并可阻断智能家居出网。

🧰

真正的工具目录

路径沙箱内的文件工具、网页搜索与阅读、带表单卡片的浏览器、办公文档导入导出、技能、会话、MCP 服务器，以及可选的 HA/MQTT 工具。

🧩

技能先验证，再运行

磁盘上的格式是一个 SKILL.md 目录。可从磁盘、URL 或 ClawHub 安装——启用前先验证能力。智能体自己写的技能只能进入 PendingLearn。

⏰

计划任务、心跳、常驻指令

重复或一次性任务，用自然语言描述“什么时候”并由你确认；心跳用于周期性回顾；常驻指令在重启后仍然存在。

把手机变成家庭智能体的窗口

EnvoyHome 的 iOS / Android Flutter 预览版是连接你自己守护进程的轻客户端。配对一次，即可通过自己的家庭连接对话、处理审批并管理同一套家庭设置。

01

无需云端账户即可配对

扫描桌面二维码、粘贴配对链接、输入 host:port，或通过 SSH 连接。手机直接接入你的家庭守护进程。

02

对话、审批与共享

按家庭档案区分的会话、内联允许 / 拒绝审批、附件与系统语音输入。共享文件和产物通过同一条家庭连接打开。

03

同一家庭，同一控制面

对话、计划任务与设置镜像桌面端。LLM、连接、技能和系统都集中在同一个已连接设置中心。

按你的方式配对

在手机上对话

八个分层，一份诚实的记忆

EnvoyHome 不把“一切都是记忆”当作设计。每一层都有明确职责、预算和注入规则——这样智能体可以记住事情，而不会悄悄改写你是谁。

  • 工作记忆是会话记录，在压缩前先落盘，而不是静默截断。
  • 常驻记忆很小且有上限：档案事实、MEMORY.md，以及最近两天的笔记。
  • 检索记忆是一个工具：情景搜索、KnowYou，以及带引用的文档知识库。
  • 持久写入经过 PendingLearn——你先接受或拒绝提议的差异，L1、L2 或技能才会改变。

L5（深度存储）是一个插槽：默认用文件，重型 RAG 后端只作为可选插件。文件始终是事实来源。

文档知识库属于你。把文件放进 knowledge/；EnvoyHome 会在本地 SQLite 中按账户建立索引，并带引用地回答。混合检索可以使用 :18793 上的 Home embed 引擎——全部在家庭机器上完成。你的文档不会被上传到 EnvoyHome 云端，因为根本没有这样的云。

智能家居，带有安全等级

接入 Home Assistant 或 MQTT broker，智能体就能读取状态，并在获得批准后调用服务。它与你现有的 hub 集成；不会变成另一个 hub。

  • 设备动作是 admin，不是写文件。无人值守的回合需要匹配的授权；脚本、场景和按钮的间接调用默认拒绝。
  • 安全等级调用永远不能靠授权放行。门锁、报警器、车库门、大门、阀门、未列入白名单的 MQTT 主题，以及任何标记为 neverUnattended 的对象，每次都要询问。
  • 未知即安全等级。新域名、厂商扩展或你没有加入允许列表的主题，会直接失败而不是猜测。
  • 先绑定，再控制。对象由已认证的 hub 注册，并通过统一入口解析——绝不相信插件自称的 id。

预览状态：Home Assistant REST 工具与 MQTT 发布今天已经可用，并附带演示 hub，可走完“对话 → 审批”的完整路径。实时入站事件管道与真实家庭的正式验收，仍需按运维清单执行。

从你已经在用的地方找到它

EnvoyMesh 轻客户端是主路径。第一方聊天插件覆盖六个常用平台，HTTP 入口负责其余场景。

EnvoyMesh 轻客户端 主路径

桌面和手机通过 home.* 直连家庭，拥有完整的设置与对话。扫描二维码、输入 host:port 或经 SSH 跳板配对一次即可。

Telegram 聊天

参考实现的机器人插件。把发送者绑定到家庭档案，回复留在同一线程。

Discord 聊天

通过官方 Bot API 的私信对话。不会在整个服务器范围内执行设备动作。

Slack 聊天

Socket Mode 应用，使用 bot 与 app token。仅支持私信。

飞书 / Lark 聊天

长连接事件，仅处理 p2p 消息——不需要公网回调地址。

钉钉 聊天

Stream Mode 机器人，用于一对一对话。

企业微信 聊天

微信客服同步，用于一对一的沟通线程。

HTTP 入站入口 兜底

一个极简的 /v1/inbound 端点，接住那些永远不会以插件形式加载的机器人。

聊天插件附带配置指南和统一的“发送者 → 档案”绑定。IM 渠道的机器人实机验证仍在进行中——预览阶段请优先使用手机轻客户端。

安全是产品本身，不是一个页面

共享家庭的默认值：沙箱开启、审批持久化、未知即拒绝。

身份

没有账户，没有云端信箱

身份就是设备上的一对 Ed25519 密钥。没有 EnvoyHome 注册、没有邮箱，也没有可被攻破的托管会话库。

审批

持久化，失败即拒绝

待审批与授权按账户落盘。重启后问题还在；超时解析为拒绝；无法确认主体身份时同样拒绝。

执行

路径沙箱与风险分级

文件工具统一经过路径沙箱。工具声明 read、write、exec、network、admin 或 sensitive——只能升级，不能降级。

隐私

隐私模式

一个硬开关：强制本地推理并拒绝云端工具。开启智能家居出网阻断后，还会拒绝设备动作与事件源通知。

账户

家庭隔离

记忆、会话、文件、授权与策略都按账户隔离。已配对设备只能代表它绑定的账户行动。

智能家居

物理世界不一样

设备动作属于 admin。摄像头、门锁与存在数据属于 sensitive，会强制本地推理。设备状态不会自动进入常驻记忆。

在家里跑起来

预览版从源码运行。你需要 Node.js 22+、pnpm，以及一份同级的 EnvoyMesh 检出。

1

检查同级依赖

EnvoyHome 通过 link: 链接 @envoymesh/*——它们不在 npm 上。同级依赖缺失或分支不对时，检查会失败关闭。

./scripts/peers-check.sh
# 或设置 ENVOYHOME_PEERS_GIT_BASE 后运行 ./scripts/fetch-peers.sh
2

安装并构建

不要在 CI=true 下安装——pnpm 严格模式的这个陷阱在本仓库有明确约定。

env -u CI pnpm install
pnpm -r build
3

启动家庭智能体

单独运行守护进程，或让桌面外壳托管它。然后创建档案、添加模型，需要时再配对手机。

pnpm run dev:daemon   # 仅守护进程
pnpm desktop:dev      # Tauri 设置外壳

从源码运行桌面应用

需要 Node.js ≥ 22 与 pnpm 10.33（根 packageManager）、一份同级的 EnvoyMesh 检出，以及桌面外壳所需的 Rust 与 Tauri CLI 前置依赖。

./scripts/peers-check.sh
env -u CI pnpm install
pnpm -r build
pnpm desktop:dev        # 缺少守护进程构建时先构建，然后启动 Tauri dev

desktop:dev 会执行 ./scripts/desktop-dev.sh：仅在缺少该文件时构建 packages/daemon/dist/bin/envoyhome-daemon.js，然后启动 tauri:dev；二进制存在后由 Tauri 托管守护进程。启动前不需要准备 provider 配置文件——首次打开的设置页会要求创建档案并选择模型提供方（预设 + 密钥，或 Local / Ollama）。

发布构建：pnpm desktop:tauri:build · 安装包：pnpm desktop:build macos（默认需要推送凭据；设置 REQUIRE_PUSH_CREDENTIALS=0 可跳过）。
